## 1. 设计原则：把"墨韵"从形容词变成规则

现状的病根不是配色难看，是**设计意图没有兑现**：标题和主按钮都套了"渐变"，而那个渐变两端对比度只有 **1.37:1**（`base.css:58`），肉眼根本看不到——付出的是 `-webkit-text-fill-color: transparent` 的代价（打印/高对比度模式下有不可见风险）。

所以本轮的第一原则是**用"墨阶"取代"渐变"**：

> **墨分五色**——焦、浓、重、淡、清。
> 层次靠**同一墨色的不同浓度**表达，而不是靠两个颜色的过渡。这正是中文语境里"墨韵"的正解，而渐变是网页模板的语汇。

三条落地规则：

| # | 规则 | 直接后果 |
|---|---|---|
| R1 | **层次用浓度，不用渐变** | 页面标题、主按钮去掉渐变，改纯墨阶；渐变只保留 Auth/Hero 背景与「AI 生成中」流光两处 |
| R2 | **金色是印章，不是装饰** | 金色（`--color-accent`）只用于"值得标记"的东西：成就、AI 产出、当前选中。不再用于大面积描边/渐变文字 |
| R3 | **衬线是标题与数字的特权** | `--font-serif` 只用于页面标题、卡片标题、统计数字；正文一律无衬线。让"书卷气"出现在结构上，而不是散落各处 |

## 2. 色彩体系

### 2.1 墨阶（替代现有 `--color-text*` / `--color-border*` 的用法约定）

保留现有色值——**它们已被 a11y 逐档校准过**（`base.css:23-51` 有完整的压深记录），改色值等于把那份工作推翻。本轮只**明确每档的职责**并把它们组织成"墨阶"：

| 令牌 | 值 | 墨分五色 | 用途（唯一） |
|---|---|---|---|
| `--color-text` | `#1a1a2e` | 焦墨 | 标题、正文强调、关键数字 |
| `--color-text-secondary` | `#5a5a7a` | 重墨 | 正文次要、列表元信息 |
| `--color-text-tertiary` | `#6f6f8a` | 淡墨 | 说明性小字、分组标题、禁用态 |
| `--color-border` | `#e8e6e1` | — | 卡片/输入框边框 |
| `--color-border-light` | `#f0eee9` | — | 分隔线、区块边界 |
| `--color-bg` | `#faf9f7` | 宣纸 | 页面底 |
| `--color-surface` | `#ffffff` | 纸白 | 卡片底 |

> **要修的具体问题**：`--color-text-tertiary` 与 `--color-success` 的**旧值仍在 9 处硬编码活着**（`#9a9ab0` ×5、`#2d8a56` ×4，见审计 §2.2），其中图谱的关系色用的正是这两个被淘汰的值。这些字面量必须收敛回令牌。

### 2.2 主色与强调色（不改值，改用法）

| 令牌 | 值 | 新用法 |
|---|---|---|
| `--color-primary` | `#0f3460` | **实底**按钮、当前选中、链接、图谱主节点 |
| `--color-accent` | `#c9a959` | 只用于：AI 产出标记、成就/里程碑、当前项的高亮描边、**衬线大数字的强调** |
| `--color-success` | `#25714a` | 完成、已掌握、通过 |
| `--color-warning` | `#936408` | 待处理、到期提醒、建议 |
| `--color-error` | `#c0392b` | 失败、危险操作、删除 |

### 2.3 卡片类型色（保持单一数据源，修正语义）

`utils/labels.ts` 的 `cardTypeColors` 已是全站唯一来源（5 处 import，这点做得对）。本轮**只补一件事**：让它与墨阶协调——四类卡片（概念/公式/问答/定义）用**墨阶 + 一个彩色**的分配，而不是四个彩色各自为政。

> 同时**删掉第二套**：`pages/KnowledgeCards.tsx:39-43` 的 `getMasteryColor()` 用的是旧色值，必须改为读 `utils/labels.ts`。

### 2.4 删除的资产（名不副实 / 零用户）

| 资产 | 处理 |

| `--graph-ink` / `--graph-ink-faint` / `--graph-paper-deep` | **接通**——图谱 canvas 改为从这些令牌取值（见 §6.4） |

## 3. 字体体系

### 3.1 中文栈要按语言维度显式覆盖

现状 `base.css:73` 是"系统字体在前、中文字族在后"，中文实际落到 PingFang / 微软雅黑——**声明了中文字族却永远不生效**。

```css
/* 正文：中文优先，按语言维度切换（学 SiYuan 的 :root:lang 做法） */
--font-sans: system-ui, -apple-system, 'Segoe UI', 'PingFang SC',
             'Microsoft YaHei', 'Noto Sans SC', sans-serif;
```

### 3.2 字体加载：**本轮不改**（按你的决定）

> **修订记录**：原方案是删掉 Google Fonts 外链、衬线改系统栈（顺带修掉 FE-4）。你决定**保持现状**，因此 `index.html` **一个字都不动**。

**"保持现状"的准确含义**（写在这里，避免日后互相误解）：

| 事实 | 说明 |
|---|---|
| 字形仍是 `Noto Serif SC`（思源宋体） | `base.css:74` 的 `--font-serif` 不变，设计的字体意图不变 |
| **能访问 Google 的环境** → 看到思源宋体 | 开发者本机、海外用户 |
| **国内 / 离线 / 企业网** → 看到 **宋体**（`SimSun`） | 字体请求挂起后的回退；这是"保持现状"在国内的实际观感 |
| FE-4 继续留在 `docs/open-source-readiness.md:553` | **本规范不关闭它**，也不重复登记它 |

**唯一保留的约定（这是用法，不是字体）**：衬线只用于**页面标题、卡片标题、统计数字**，字号 ≥ 1.25rem。宋体在大字号下是体面的，它糟糕的表现集中在小字号正文——而正文一律无衬线。

> 将来若要修 FE-4，回看本节的原始分析即可（两个候选方案：系统栈 / 自托管子集化），不重复论证。

### 3.3 标题层规则（现在完全缺失）

现状：18 个页面各自内联写 `<h1 style={{fontSize}}>`，**五档字号并存**（1.25 / 1.5 / 1.75 / 2 / 认证页自有），7 处带渐变、3 处不带，**没有页面标题组件**。

新规则（单一来源）：

| 层级 | 字体 | 字号 | 字重 | 字距 |
|---|---|---|---|---|
| 页面标题 h1 | 衬线 | `--text-xl` | 600 | `0` |
| 区块标题 h2 | 衬线 | `--text-lg` | 600 | `0` |
| 卡片标题 h3 | 衬线 | `--text-base` | 600 | `0` |
| 正文 / 界面文字 | 无衬线 | `--text-base` / `--text-sm` | 400 | `0` |
| 统计大数字 | 衬线 | `--text-2xl` / `--text-3xl` | 700 | `-0.01em` |

> ⚠️ **中文字距必须归零**：现在 `components.css:402-407` 给所有标题加了 `letter-spacing: -0.01em`——那是为**拉丁字形**调的负字距，中文字形会被挤在一起。

## 4. 图标体系（自绘 SVG）

### 4.1 前提条件：按公开事实标准画，而不是随意画

自绘的最大风险不是"画得慢"，是**画出一套只有作者能维护的私有规范**——半年后要补一个图标，没人知道该用多粗的线、多大留白。

所以自绘集的硬约束是：**几何参数完全对齐 Lucide / Obsidian 的公开规范**（它们是这个领域的事实标准），只把"图形本身"换成我们自己的：

| 参数 | 值 | 来源 |
|---|---|---|
| 画布 | `viewBox="0 0 24 24"` | Lucide / Obsidian 一致 |
| 内容区 | 20×20，四周留 2px 呼吸 | Obsidian 规范 |
| 线宽 | **1.5px**（初稿），全站锁死 | 本项目判断：中文笔画细，2px 图标会抢戏 |
| 端点/拐角 | `stroke-linecap="round"` `stroke-linejoin="round"` | Lucide / Obsidian 一致 |
| 颜色 | `stroke="currentColor"`（**绝不写字面色值**） | 现状已达标：SVG 属性里 0 处字面色值 |
| 填充 | `fill="none"` | 同 |
| 尺寸 | 只允许 16 / 20 / 24 三档，由 `<Icon size>` 控制 | 现状是 16 与 18 混用 |

**这样做的额外好处**：将来若想改用 Lucide，因为网格与线宽一致，可以逐个平滑替换，不需要重画布局。

### 4.2 唯一出口

```
frontend/src/components/Icon.tsx          ← 唯一图标出口
frontend/src/components/icons/*.tsx       ← 每个图标一个文件（或单文件多导出）
```

对外只暴露**语义名**，不暴露图形名：

```tsx
<Icon name="review-due" size={16} />
```

> 现状对照：`components/` 下**没有任何 Icon 组件**，侧栏图标是 `Sidebar.tsx:22-54` 里 13 个硬编码 Unicode 码点。

## 5. 几何体系：把 4 套散值收敛成 4 张表

### 5.1 字号（**已按你的决定改为：本轮零视觉变化**）

> **修订记录**：原方案是把 34 个值收敛成 9 档，但那会让 `0.8rem`（104 处）从 12.8px 变成 13px，**全站 UI 文字普遍位移 0.2~0.5px**。你决定「保持字号不变」，因此本节改为**只给现状命名，不改任何已有声明的值**。

**做法**：把现状里"事实上的阶梯"登记成令牌，令牌值 **逐字等于现状值**；本轮**不替换任何存量声明**，只规定"新写的样式必须用令牌"。

| 令牌 | 值 | 现状出现 | 定位 |
|---|---|---|---|
| `--text-2xs` | 0.7rem / 11.2px | 23 | 推荐档 |
| `--text-xs` | 0.75rem / 12px | 65 | 推荐档 |
| `--text-sm` | **0.8rem / 12.8px** | **104** | 推荐档（UI 主力） |
| `--text-sm-alt` | 0.85rem / 13.6px | 35 | ⚠️ 存量专用，勿新增 |
| `--text-base` | 0.875rem / 14px | 60 | 推荐档 |
| `--text-base-alt` | 0.9rem / 14.4px | 34 | ⚠️ 存量专用，勿新增 |
| `--text-md` | 1rem / 16px | 31 | 推荐档（阅读正文） |
| `--text-lg` | 1.1rem / 17.6px | 5 | 推荐档（区块标题） |

## 6. 展现形式规范

### 6.1 页宽：六档 → 三档

根因是 `App.module.css:55` 把全局 `max-width:1200px` 改成了 `none`，页宽于是由各页内联 `maxWidth` 各写各的（600/640/700/760/800/960/全宽）。

| 令牌 | 值 | 用于 |
|---|---|---|
| `--width-reading` | 760px | 阅读、答题、表单、评估（注意力聚焦） |
| `--width-standard` | 1200px | 列表、卡片、管理页（默认） |
| `--width-full` | 100% | 图谱、分屏编辑 |

统一由 `App.tsx` 的 `<main>` 按路由决定，**页面内不再写内联 `maxWidth`**。

### 6.2 新增两个共用组件

| 组件 | 解决什么 | 现状 |
