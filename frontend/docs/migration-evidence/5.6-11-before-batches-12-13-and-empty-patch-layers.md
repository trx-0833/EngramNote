# 5.6 迁移前：序 12 / 序 13（两张补丁层清空）的规则清单 + 逐条去向审计

`refinements.css` 与 `responsive.css` 是两层"后加载覆盖前面"的补丁，**清空它们**（而不是删文件 —— `mobile-input-font-size.test.ts` 断言每个
`src/styles/*.css` 都被 `main.tsx` 引入）是 5.6 的最后两步。
这一批的证据不是"逐条保留"（规则只是换了归属），而是**去向审计**：
迁移前那份样式表里的每一条规则，都能在工作区的某个 CSS 里找到
"上下文 + 选择器（类名 kebab→camel 归一）+ 声明逐字相同"的那一条，
或者落在显式例外表里（每条都写明依据）。

例外有三类：
1. **13 条属性选择器 `[style*="rgba(0,0,0,0.5)"] …`**：真 Chromium 实测该选择器
   命中 **0** 个元素（React 走 CSSOM 赋内联值，浏览器把它序列化成带空格的
   `rgba(0, 0, 0, 0.5)`），也就是说这些规则**迁移前就从未生效**，删它是可证明的空操作；
2. **`:root` 的 `--page-pad-y-*`**：随 `.app-layout` 收进 `App.module.css` 的 `.appLayout`
   （选择器变了，值一字未改；`relocations` 里有双向自检）；
3. **5 个零引用的"预留语义化类"**（`.link-modal` / `.material-list-item*` / `.type-badge*`，6 条规则）：
   序 12 逐字搬进 `components.css`，收尾轮（死代码清理）**整条删除** ——
   `src/**` 的 TSX/TS grep 0 处、运行时拼类名 0 处，`LinkManagerModal.tsx` 用的是内联 style。
   证据 `docs/migration-evidence/5.6-13-dead-css-cleanup.md`。
