## 为什么不动

1. 5 条规则**全部**是 `.markdown-body.adhd-reader-active …` 的后代选择器，
   而 `.markdown-body` 自己按判据必须留全局：三个**不相邻**功能在用它
   （`pages/notedetail/MarkdownReader.tsx`、`pages/notedetail/EditSplitView.tsx`、
   `components/NoteAskPanel.tsx` —— 后者还 `document.querySelector(".markdown-body")`），
   正文 HTML 又来自 `marked` 渲染的字符串（`css-convention.md` §4 第 2、4 条）。
2. 四个 `.adhd-*` 类名的**全部写入点**都在 `src/hooks/useAdhdReader.ts`
   （`classList.add/remove/contains` 与一次 `className = "adhd-line-marker"` 整体赋值）——
   逐处表见 `src/styles/markdown.css` 文件头。三条判据逐条对照：
   "改成语义查询"不行（这些类名是给 `marked` 生成的块打标记的唯一手段）、
   "从模块导出常量"不行（写入点所在的 `src/hooks/**` 不在本批允许改动的文件范围内，
   且为 4 个类名让通用 hook 去 import 页面模块等于颠倒归属）、
   "留全局"成立（第 1 条已给出判据依据）。
3. `utils/markdown.ts` 不注入这些类名（grep 0 命中）；`responsive.css`
   对 `.adhd-*` 也 0 命中 —— 不存在"补丁层还在命中它"的问题。

⚠️ 硬塞进模块只能写成 `:global(.adhd-block)` 之类，那等于一个字符都没被
作用域化，却把"这些类名是全项目约定"藏进一个页面模块里（规范 §4 末尾的"半搬"）。

.markdown-body.adhd-reader-active > .adhd-block.adhd-current-block { border-radius: var(--radius-sm); box-shadow: 0 0 0 4px var(--color-accent-light) }
.markdown-body.adhd-reader-active > .adhd-block.adhd-current-block a { pointer-events: auto }
.markdown-body.adhd-reader-active .adhd-line-marker { position: absolute; z-index: 1; pointer-events: none; display: none; height: 3px; background: linear-gradient(90deg, var(--color-accent), rgba(37, 99, 235, 0.2)); border-radius: 2px; transition: top 0.08s ease, left 0.08s ease, width 0.08s ease }
