## 0. 结论

**v1 坏了；v2 与 v3 都修好了；v2/v3 之间的差异比它们与 v1 的差异小得多。**

| 维度 | v1 | v2 | v3 |
|---|---|---|---|
| 题型种类 | **1 种** | **3 种** | **3 种** |
| 四选一占比 | **100%** | 28% | 60% |
| 难度档位 | 2 档（79% easy） | 3 档（71% medium） | 3 档（86% medium） |
| 产出 `hard` | ❌ | ✅ 1 道 | ✅ 2 道 |

- **v1 的「坏」被大规模证实**：v1 在 **10 篇 / 300 道题**上产出 **100% `choice`**、
  93% `easy`。计划 §2.3 的判断（题型与难度写死在提示词里）成立，
  「不修就白跑」也成立。
- **v2 与 v3 都修好了题型**：两版都出现 `fill_blank` 与 `short_answer`，
  都不再是「清一色四选一」。
- **v3 并不全面优于 v2**（这一点与只有 2 篇样本的小样阶段印象**不同**）：
  - v3 的四选一占比**更高**（60% vs 28%）；
  - v3 的难度**更集中**（86% medium vs v2 的 71%）；
  - 但 v3 在 `发电厂电气…第二章-第三节` 上给出了三档（medium 17 / easy 11 / hard 2），
    而 v2 在那篇上是 100% medium；
  - v2 则在 `第二章第三节笔记` 上给出三档，v3 在那篇上是 100% medium。
  - 也就是：**两版各有过校正，谁也做不到「按比例分布」**。

## 4. 必须一起看的限制

1. **有效样本 3 篇**。「v2 与 v3 谁更好」是 **n=3** 的结论，不足以定论。
2. **难度多样性要逐篇看**：两版都能给出三档，但都不稳定（各有一篇是 100% medium）。
3. **v2 那篇 185,944 tokens 异常高** —— 未查明是重试还是提示词更长，
   **报告里不猜**。它是唯一一个明显偏离的量。
4. 题目总数在三版下都是 30/篇：**总数不由版本决定**。

## 5. 未完成与续跑方式

计划 26 篇 × 3 版 = 78 轮，实际完成 16 轮（v1 10 篇 + v2 3 篇 + v3 3 篇）。
瓶颈是**每篇 5–18 分钟的「理解 + 嵌入」**，不是出题。

```powershell
cd backend
# 1) 先扩 v1
& "$env:USERPROFILE\anaconda3\envs\mineru_env\python.exe" scripts\rerun_understanding.py `
    --tmp data/_uxwalk --versions 1 --min-cards 1 --skip-done

# 2) 再给这批补 v2/v3（`--note-ids-from` 保证是同一批语料）
& "$env:USERPROFILE\anaconda3\envs\mineru_env\python.exe" scripts\rerun_understanding.py `
    --tmp data/_uxwalk --versions 2,3 `
    --note-ids-from data/_uxwalk/rerun/snapshot-v1.json
```

⚠️ `--note-ids-from` 是本次为此加的：驱动器的选笔记规则是「按当前卡片数升序」，
而**重跑会改变卡片数** ⇒ 「再取前 N 篇」取到的不是同一批，三版对照会错位。
