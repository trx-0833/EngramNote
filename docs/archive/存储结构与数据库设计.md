## 一、文件树结构

项目所有持久化文件统一落在 `backend/data/` 下（可通过配置重定向）；其中 **Vault 根** 采用「项目隔离 + 状态旁载」结构，本地文件系统与 MinIO 对象存储共用同一 object-name 约定。

```mermaid
graph TD
    subgraph DATA["backend/data/ 数据根目录"]
        DB["db/ · SQLite 数据库<br/>engramnote.db"]
        VAULT["storage/ · Vault 根（本地模式）<br/>可配置指向任意磁盘目录"]
        CHROMA["chroma/ · 去重向量库"]
        CELERY["celery/ · broker + 任务结果"]
        MODELS["models/ · 嵌入模型缓存（2GB+）"]
        LOGS["logs/ · 运行日志"]
    end

    subgraph VAULT_TREE["Vault 目录树 · {user_id}/{project_slug}/"]
        U1["{user_id}/"]
        U1 --> P1["{project_slug}/ 项目目录"]
        U1 --> INBOX["inbox/ 未归属笔记兜底"]
        P1 --> SRC["source/<br/>原始文件 · 只读区"]
        P1 --> OUT["output/"]
        OUT --> MD["output/markdown/<br/>{base}.md 原始转换（只读）<br/>{base}.clean.md 清洗工作副本"]
        OUT --> META["output/meta/<br/>{base}.json 状态旁载镜像<br/>project.json 项目级清单"]
        OUT --> ASSETS["output/assets/ · 预留"]
        P1 --> HIST["history/versions/<br/>v{N}.md 版本归档"]
        P1 --> CACHE["cache/ · 预留（OCR/ASR）"]
    end

    MD -. 命名关联法则 .-> SRC
    META -. 写穿镜像（非权威） .-> DB

    style VAULT fill:#f2f7ff,stroke:#4b3fe3
    style U1 fill:#f2f7ff,stroke:#4b3fe3
```

**命名关联法则**：`source/{base}{ext}` ↔ `output/markdown/{base}.md`（仅扩展名不同），保证脱离数据库也能通过文件名完成溯源。

## 三、设计要点速记

| 关注点 | 说明 |
|---|---|
| 状态权威源 | `notes.status` 是唯一权威，前端轮询 DB；`output/meta/*.json` 仅为物理旁载镜像 |
| 文件↔DB 关联 | 通过 `notes` 表的 `original_file_path / original_md_path / clean_md_path` 三个对象路径引用 |
| 用户隔离 | 所有路径以 `{user_id}` 为第一段，数据库查询也强制带 `user_id` 条件 |
| 知识卡片溯源 | `knowledge_cards.note_id` 可回溯到来源笔记；`card_relations` 无向对去重（`card_id_1 < card_id_2` 排序存储） |
| 复习调度 | SM2 算法参数（interval/repetition/easiness_factor）内嵌于 `quiz_items`，作答历史在 `review_logs` |
