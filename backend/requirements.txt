# ============================================================
# EngramNote 后端运行依赖（**用户装这一份**）
# ============================================================
#
# 用法：
#     pip install -r requirements.txt          # 跑起服务所需
#     pip install -r requirements-dev.txt      # 另有测试/lint 依赖
#
# ## 这份清单的判据是"全新装完能不能跑"，不是"CI 能不能过"
#
# 2026-09-23 修正：此前测试依赖与运行依赖混在一起，同时**漏了 3 个模块级硬依赖**，
# 后果是陌生访客照 README 装完，**PDF 上传路径直接 ModuleNotFoundError**
# （PDF 恰恰是本产品最主要的入口）。漏掉的三个与它们的 import 位置：
#     pypdfium2  app/services/mineru/intake.py:22   （模块顶层，无条件）
#     Pillow     app/services/mineru/intake.py:23   （模块顶层，无条件）
#     psutil     app/services/embedding_service.py:54（函数内，嵌入可用性探测）
# 它们此前只登记在 requirements-test.txt 里，而那是"CI 能过"的清单。
#
# ## 版本策略
#
# 直接依赖用 `~=` 锁定主次版本（允许补丁浮动）。`pip freeze` 级别精确锁定是
# 独立批次的事；声明与实际的差异用一条命令可见：
#     python backend/scripts/check_dependency_drift.py
# （只读、不升级、不联网；处置口径见 docs/security-scan.md）
#
# ## 刻意**不**在这里的东西
#
#   - pytest / ruff 等 → requirements-dev.txt（用户不需要它们才能跑服务）
#   - torch / qwen-asr   → 重量级可选，见 requirements-asr.txt
#   - mineru             → 仅本地解析需要，见 requirements-mineru.txt
#                           （云端 vlm-http-client 是纯 HTTP，**不依赖**该包）
#   - asyncpg / minio / redis → 项目明确不引入的中间件（见 AGENTS.md 的已否决方向）
#
# ⚠️ 2026-10-21：`pyyaml` 曾列在上面这一节，现**已移入下面的正式清单** ——
#    它是 `config_loader.py:14` 的模块顶层无条件 import，云端路径同样要用，
#    归到可选清单会让全新环境在 PDF 路径上直接 ModuleNotFoundError。

# ---- Windows：文件 broker 的硬依赖（2026-11-08 补）----
# `kombu.transport.filesystem` 在 Windows 上 **模块顶层** `import pywintypes`，
# 缺它时 `celery worker` 直接起不来（不是告警，是 traceback 退出）：
#     File "…/kombu/transport/filesystem.py", line 115, in <module>
#       import pywintypes
#     ModuleNotFoundError: No module named 'pywintypes'
# 而本项目的队列就是 filesystem broker（docs/sqlite-single-writer.md / start.bat），
# 所以这不是可选件：全新 Windows 环境按 requirements.txt 装完照样起不了 worker。
# 真机实测（2026-11-08，conda env aiforlearn）：装上 pywin32 后 worker 立刻可用，
# 之前所有异步任务（MinerU 转换 / 清洗 / 理解 / ASR）都跑不起来。
# ⚠️ 标记用**单引号**：`pyproject.toml` 那边是双引号字符串，
# `test_packaging_metadata` 逐字比两份清单的约束串，引号风格不同会判红。
pywin32>=306; sys_platform == 'win32'
