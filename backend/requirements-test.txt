# 测试与 lint 依赖（CI 与本机共用的单一来源）
#
# > **2026-09-23 补记：本文件与 `requirements-dev.txt` 的分工**
# > - 本文件 = **CI 装的那一份**：钉在"测试实际会 import 到什么"，
# >   刻意**不钉版本**（CI 的判据是"用最新可用版本也能过"）。
# > - `requirements-dev.txt` = **贡献者读的那一份**：解释每个依赖为什么存在。
# > - `requirements.txt` = **用户装的那一份**：判据是"全新装完服务能不能跑"。
# > 三者判据不同，因此不能合并；但"同一个包写两遍"要尽量避免 ——
# > 目前它们各自登记测试真正需要的子集，未使用的包不登记。
#
# ## 为什么单独一个文件
#
# 最初 CI 的依赖清单是**手抄**在 `.github/workflows/ci.yml` 里的，结果与
# 实际依赖漂移：漏掉了 `requirements.txt` 第 14 行的 numpy，而
# `app/services/graph_service.py`、`asr/asr_engine.py` 等模块在 import 阶段
# 就会 `import numpy`。后果是 CI 上 **64 failed / 4 errors**，
# 而本机全绿 —— 因为本机的 conda 环境装了全套依赖，掩盖了缺失。
#
# 手抄清单必然漂移。这里改为单一来源，CI 直接 `pip install -r` 本文件。
#
# ## 为什么是"子集"而不是直接装 requirements.txt
#
# `requirements.txt` 里的 sentence-transformers / chromadb / openai / soundfile
# 是 GB 级重量依赖（会拉 torch），而单元测试**不加载模型**
# （见 tests/conftest.py 的网络守卫：默认阻断一切真实外呼）。
# CI 装它们只会让反馈循环变慢，不会提高覆盖率。
#
# 因此本文件的选取标准是：**测试实际会 import 到的运行期依赖**。
# 新增测试若用到新的运行期模块，请同步在此登记。
#
# 用法：
#     pip install -r requirements-test.txt
#     python -m pytest -q
