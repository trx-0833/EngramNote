### 7.4 结论与一个优化建议

脚本可用，退出码语义正确（成功 0 / 失败 1），默认 Python 路径解析正确。

**但 66 秒对 pre-push 偏慢**，瓶颈在 eslint（26s，且第二次没有变快，说明未启用缓存）。

两个可选优化（都不属于本批范围）：

1. **给 eslint 加 `--cache`**
   ```
   "lint": "eslint src/ e2e/ scripts/ --cache --cache-location node_modules/.cache/eslint/"
   ```
   预期从 26s 降到 3–5s。代价：改 `frontend/package.json`（属改既有文件，需单独决策）。

2. **拆分前后端钩子**：pre-commit 跑 eslint（只对 staged 文件，秒级），pre-push 只跑 vitest（39s）。这样 pre-push 从 66s 降到约 40s。

当前 `lefthook.yml` 里 pre-push 写的是 `verify.sh fast`，如果将来启用后发现太慢，优先做第 2 条（不改 package.json，只改 lefthook.yml）。
