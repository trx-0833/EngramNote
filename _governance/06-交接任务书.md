## 2. 环境前置（不满足会得到**假失败**）

**你多半在 Windows PowerShell 5.1 里**（不是 pwsh 7）。这有两个后果：读 UTF-8 中文文件会乱码；`npm` 可能被 ExecutionPolicy 拦住。

```powershell
# 1) Python 指向装了 ruff/pytest 的环境（绝对路径，不要靠 PATH 里的 python）
$env:PYTHON = "D:\conda\envs\aiforlearn\python.exe"

# 2) gitleaks 加入 PATH
$env:PATH = "$env:PATH;$env:LOCALAPPDATA\Microsoft\WinGet\Packages\Gitleaks.Gitleaks_Microsoft.Winget.Source_8wekyb3d8bbwe"

# 3) 自检（三条都必须成功，否则不要往下走）
& $env:PYTHON -m ruff --version
gitleaks version
& "D:\Program Files\Git\bin\bash.exe" -lc "echo bash-ok"
```

**关键警告：以上设置只对当前 shell 有效。** 每个新开的 shell 都要重设。
用户级 PATH 已写入 gitleaks 目录，但**已打开的进程不会继承**——表现为"明明装了却 command not found"。

**症状对照表**：

| 报错 | 实际原因 | 修法 |
|---|---|---|
| `No module named ruff` / `pytest` | `python` 指向 `D:\miniforge3\python.exe`（base 环境） | 用 `$env:PYTHON` 绝对路径 |
| `sh: line 1: gitleaks: command not found` / `exit status 127` | gitleaks 不在当前 shell 的 PATH | 见上 |
| 读 `.md` / `.coveragerc` / `.toml` 中文全是乱码 | **PS 5.1 用 ANSI 解码 UTF-8** | 用 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`，或干脆用 `bash cat` |
| `LF will be replaced by CRLF` | `core.autocrlf=true` | **噪音，忽略**（该文件本来就是 LF） |

## 3. 六段式执行规范

### 3.1 先读什么（顺序不能乱）

1. `AGENTS.md` —— **§2 已否决方向**、**§3.5 环境与命令**
2. `_governance/05-执行日志.md` —— 最近三轮决策与踩过的坑
3. 相关 `docs/`：架构 `docs/architecture.md`、运维 `docs/operations.md`、
   当前主线 `docs/overhaul-plan.md`（**唯一权威**；`docs/decisions.md` 已声明只读归档）
4. 你要改的文件**同目录的既有写法**

### 3.2 怎么定范围：用工具，不要凭感觉

```bash
node scripts/risk.mjs --files <你打算改的文件...>
```

| 分数 | 档位 | 要求 |
|---|---|---|
| <20 | LOW | lint + 单测即可 |
| 20–50 | MEDIUM | 改完必须跑 `verify.sh fast`，报告里贴结果 |
| >50 | HIGH | **先出方案再动手**，改完还要跑覆盖率，必须写回滚方式 |

### 3.3 怎么改

- **单一意图**：一次提交只做一件事
- **不顺手重构**：看到别处过时/有问题，**只记录在报告里**，不要一起改（会让 diff 无法审查，也会让 review 分不清哪部分是任务要求的）
- **不新增依赖**
- **遵守既有约定**：跟着同目录走，不要套通用最佳实践

### 3.4 怎么验证（**两条命令分开跑**）

```bash
bash scripts/verify.sh fast          # ruff + eslint + vitest，约 42s
cd frontend && npm run docs:links    # 改过 .md 才需要；验证相对链接
cd frontend && npm run docs:tables   # 改过 .md 表格才需要
```

⚠️ **不要把两条串在同一条 `bash -lc` 里**——后一条的输出与退出码会丢失，容易误判成"没跑"。

⚠️ `fast` **不含 pytest**。改过后端逻辑必须另跑：
```bash
cd backend && python -m pytest tests/<相关文件>.py -q
```
全量 `python -m pytest -q` 是 1760 用例 / 约 32 分钟，除非必要别跑。

### 3.5 怎么提交（钩子会咬人）

```bash
git add <具体文件>          # 不要 -A
git commit -m "type(scope): 一句话说清为什么"
```

- pre-commit 会自动**修复** import 排序与格式并重新 stage；只有不可自动修复的问题（如 `F821`）才会真正拦住
- **lefthook 不在 PATH**，无法手动预跑。想预跑用完整路径：
  `"$env:LOCALAPPDATA\Microsoft\WinGet\Packages\evilmartians.lefthook_*\lefthook.exe" run pre-commit`
- 逃生口是 `LEFTHOOK=0 git commit`。**不要用 `--no-verify`**——那会把真实的 lint/密钥问题一起放过

### 3.6 什么时候必须停下来问人

- 删数据/文件（**尤其 `backend/data/`**，那是真实笔记不是夹具）
- 装占磁盘的东西（模型权重、新依赖）
- 改产品语义或接口契约（`backend/app/api/`、`schemas/`、`openapi.json`）
- 推翻 `AGENTS.md` §2 的既定决策
- 动 `alembic/versions/` 已有迁移（只能新增）
- **发现文档与代码冲突，但任务范围限定"只改某一段"** → 报告冲突，别擅自扩范围（真实案例：`docs/operations.md` 的 jq 字段名与 `logging_config.py` 实际输出不一致，接手者按约束只报告未改，这个判断是对的）

## 5. 已踩过的坑（11 条，别重踩）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | 用 base 环境的 python | `No module named ruff` | 设 `$env:PYTHON` 绝对路径 |
| 2 | gitleaks 不在 PATH | `exit status 127` | 加 PATH；注意新 shell 要重加 |
| 3 | **`.ps1` 存成无 BOM UTF-8** | PS 5.1 按 ANSI 解码 → 中文乱码 → **报错行号完全漂移** | `.ps1` 必须带 BOM；`.json` 必须**不**带 BOM |
| 4 | 用编辑器工具改 `.ps1` | **工具会静默去掉 BOM** | 改完检查首 3 字节是否 `EF BB BF`，或改用 PS 写入 |
| 5 | 覆盖率配置放根 `pyproject.toml` | 配置"写了但没生效"（TOTAL 不变） | 放 `backend/.coveragerc` |
| 6 | 变异测试配置放仓库根 | Stryker 静默退化为默认 runner，只发现 1 个测试 | 放 `frontend/stryker.config.json` |
| 7 | 对没有测试的文件跑变异 | 变异体全 timeout | 先确认有 `*.test.ts` |
| 8 | `git add -A` | 会把未跟踪的私有产物一起提交 | 只 add 具体路径 |
| 9 | **在 MD 表格行末尾追加内容** | 加在结束符 `\|` 之后 → 多一列，`docs:tables` 报缺陷 | 加在 `\|` **之前** |
| 10 | **PS 5.1 读 UTF-8 文件** | `Get-Content` 中文全乱码，容易误判"文件坏了" | 用 `[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` |
| 11 | **只验证"不报错"，不验证"行为对"** | 脚本 exit 0，但逻辑根本没执行 | 造数据验证输出，如下 |

### 坑 11 的完整案例（最重要）

`scripts/backup.ps1` 的三档保留策略曾因"按行拼接重写脚本"漏掉了三个变量定义（`$dirs`/`$now`/`$keep`）：

- 症状：脚本 **exit 0、不报错**，但 `[prune] 保留： ｜ 删除：0` —— 那一行是空的
- 后果：旧备份**永不删除**，`_backup/scheduled` 只增不减（38MB/次）
- 发现方式：不是读代码看出来的，是**造 8 个不同年龄的快照、逐条核对是否保留**时对不上预期
- 修完还暴露了第二个缺陷：weekly 窗口**没有上界**，40/50 天的快照被 weekly 抢先吃进，导致 monthly 分档错乱（应删 2 个实际只删 1 个）
- 最终判据：`daily=3 weekly=2 monthly=2 ｜ 删除：2`，8 条预期全绿

**教训：判据要落在行为上。** `if` 有没有进、循环跑了几次、输出对不对——这些都不能靠"脚本没报错"推断。

## 5.5 「改名」是一次影响面变更

把 CI job `docker-nginx-config` 改名为 `nginx-config-guard` 后，**5 处活文档仍在引用旧名**，其中一处是当前唯一权威的 `overhaul-plan.md`。

改名时必查四类引用：

```bash
git grep -n '<旧名>' -- '*.md' '*.py' '*.ts' '*.yml' 'scripts/'
```

| 文档性质 | 处置 |
|---|---|
| 活文档（README / CONTRIBUTING / overhaul-plan） | 改名 + 标注原名，行号引用一并更新 |
| 历史快照（open-source-readiness 等核查报告） | **不改结论**，只追加"该 X 已于 YYYY-MM-DD 改名" |
| `_governance/` 记录 | 保留旧名（历史事实） |

**本地看不到的风险**：如果 GitHub 分支保护把旧 job 名列为 required check，改名后该 check 会一直 pending，PR 永远合不了。改名前先去 Settings → Rules 确认。

- [ ] `git status` 只显示**目标文件**（以及交接任务书自身，如果它还没被跟踪）

- [ ] 若 MEDIUM 以上：报告里有 `risk.mjs` 分数与回滚方式
- [ ] 没有新增依赖、没动 `alembic` 历史迁移、没碰 `backend/data/`
- [ ] 没有用 `--no-verify`

## 7. 出问题怎么收

```bash
git status --short          # 看改了哪些
git diff --stat
git checkout -- <path>      # 退回单个文件
git reset --soft HEAD~1     # 退回最近一次提交（保留改动）
git revert <sha>            # 彻底回退一次提交
```

总原则：每条改动独立提交，任何一条都能单独 `revert`。需要"一次撤销一大片"说明粒度不够。
