## D-05 容器化文件怎么处置

**现状（已实测，纠正了先前的错误信息）**
- `AGENTS.md:18` 把容器化列为**已否决方向**（该行确实存在于本仓库）
- `docker-compose.yml` 头注释自述"**未验证：本项目从未构建或运行过这些容器**"（存在于 `docker-compose.yml:4`）
- 文件：`docker-compose.yml`、`backend/Dockerfile`、`frontend/Dockerfile`、`frontend/.dockerignore`、`frontend/nginx.conf`
  - **`backend/.dockerignore` 不存在**（先前记错）
- CI 的 `docker-nginx-config` job 在 **`ci.yml:518-564`，共 4 步**（不是 3 步）：
  1. nginx 必须有 `client_max_body_size`（防 >1MB 上传 413）
  2. nginx 必须 `proxy_buffering off`（防 SSE 被缓冲）
  3. `frontend/.dockerignore` 必须排除 `node_modules`
  4. `frontend/Dockerfile` 必须 `COPY package-lock.json` + `RUN npm ci`

**新发现（直接改变成本估算）**

`frontend/nginx.conf` 是**通用规则与容器路径混写**：

| 段落 | 内容 | 是否容器专属 |
|---|---|---|
| `client_max_body_size 500m` | 上传上限 | ❌ 通用（任何 nginx 部署都要） |
| `proxy_buffering off` | SSE 不缓冲 | ❌ 通用 |
| `try_files ... /index.html` | SPA 回退 | ❌ 通用 |
| 安全头（nosniff/X-Frame/Referrer） | — | ❌ 通用 |
| `root /usr/share/nginx/html` | 镜像内路径 | ✅ 容器专属 |
| `proxy_pass http://backend:8000` | compose 服务名 | ✅ 容器专属 |

**活文档里对 docker/compose 的引用共 49 处**：
`README.md` 4、`CONTRIBUTING.md` 1、`docs/decisions.md` 2、`docs/open-source-readiness.md` 11、`docs/overhaul-plan.md` 20、`docs/security-scan.md` 11。

**选项（已按新证据修订）**

| 选项 | 做法 | 成本 | 风险 |
|---|---|---|---|
| A（原推荐，现已不推荐） | 全删容器文件 + CI job | 高：要同批改 6 份文档 49 处引用，漏一处就是失效引用 | 中 |
| B | 全删，含 `nginx.conf` | 最高 | **高**：会丢掉"413 / SSE 缓冲"这两条只有生产才暴露的知识与唯一自动守卫 |
| **C（现推荐）** | **保留全部文件，只改头部标注**：三个容器文件加"未验证/勿作部署路径，保留原因是记录了 X/Y 兼容性结论"；`nginx.conf` 头部说明"容器专用路径 + 通用规则，非容器部署需改 root 与 proxy_pass"；CI job 改名 `nginx-config-guard` 并删第 3 步（`.dockerignore` 只在构建时有用），**保留第 1、2 步** | 低：改 4 个文件头 + CI 一处 | 低 |
| D | 只删 `docker-compose.yml` 与两个 Dockerfile，保留 `nginx.conf` 与全部 CI 守卫 | 中：仍要改 README 的部署章节 | 低 |

**我的推荐：C**。理由：
1. 49 处文档引用让"删干净"的成本远超收益
2. `nginx.conf` 的通用规则（413/SSE/安全头）对将来任何 nginx 部署都成立
3. Dockerfile 里记录了兼容性结论（如 `libgl1` 替代已废弃的 `libgl1-mesa-glx`）
4. C 消除的是"**读者被误导**"这个真问题，而不是"文件存在"这个假问题

**不决定的后果**：仓库继续同时发出三个矛盾信号（AGENTS 说已否决、compose 说未验证、CI 却天天校验它），未来的 agent 与贡献者会再次踩进来。

## D-03 变异测试走哪条路

- WSL 只装了 `docker-desktop` 发行版（**不能跑 pip/python**），要跑 mutmut 需先 `wsl --install -d Ubuntu`

**选项**

| 选项 | 覆盖范围 | 代价 |

| **A（推荐）** | 只做前端 Stryker（`src/utils`、`src/hooks`） | Python 侧无变异测试；但前端是本项目 churn 最高的区域（30 天 443 次改动） |
