## 2. `lefthook.yml`

**当前状态**：文件已放，**未安装 lefthook，不生效**。
**用途**：pre-commit 跑 ruff/eslint/prettier/gitleaks；pre-push 跑 verify.sh。

### 启用步骤

```powershell
# 1) 安装（任选一种）
scoop install lefthook
# 或：npm i -D lefthook（会写入 frontend/package.json，属于改依赖，需单独决策）

# 2) 安装 git 钩子
cd D:\engramnote
lefthook install

# 3) 验证
git commit --allow-empty -m "test hook"     # 应触发 pre-commit
git reset --soft HEAD~1                     # 撤掉这个空提交
```

### 启用前必须确认

- [ ] `gitleaks` 已安装（否则 pre-commit 的 secrets 步骤会失败）
- [ ] 已知晓 `SKIP_VERIFY=1 git push` 是逃生口，并写进 `AGENTS.md`
- [ ] 用一次真实提交测试过耗时（目标 <10s；超过则把 prettier 移到 pre-push）

### 启用后影响

- **每次 commit 会变慢**（预计 3–8s）
- 如果 IDE 正在自动保存，`{staged_files}` 可能与其他改动冲突
- 若 lefthook 未装而 `lefthook.yml` 存在：**无影响**（这正是当前状态）

### 回滚

```powershell
lefthook uninstall
Remove-Item lefthook.yml
```

## 3. `.gitleaks.toml`

**当前状态**：未启用（gitleaks 未安装）。
**用途**：密钥扫描的 allowlist（避免测试里的假 key 造成误报）。

### 启用步骤

```powershell
scoop install gitleaks
cd D:\engramnote

# 先全历史跑一次，看命中
gitleaks detect --no-banner --redacted --report-format json --report-path .tmp/gitleaks.json

# 把真阳性处理掉，把假阳性加进 .gitleaks.toml 的 allowlist
# 再跑一次确认干净
gitleaks detect --no-banner --redacted
```

### 启用后影响

- 接入 pre-commit 后，提交含疑似密钥会**被拦住**（这是目的）
- 若 allowlist 写得太松，会漏真阳性；太紧会频繁误报 → 首次务必人工看一遍全历史结果

### 回滚

删除 `.gitleaks.toml`；gitleaks 恢复默认规则（更严，误报更多）。

## 6. `scripts/backup.ps1`

**当前状态**：未注册计划任务，不自动运行。
**用途**：把备份触发器从 celery-beat 移出应用，改为系统级定时任务。

### 启用步骤

```powershell
# 1) 手动试跑一次（不注册任务）
cd D:\engramnote
powershell -File scripts\backup.ps1

# 2) 确认产出
Get-ChildItem _backup\scheduled | Sort-Object Name -Descending | Select-Object -First 3

# 3) 注册每日 03:00
schtasks /create /tn "EngramNote-Backup" /tr "powershell -NoProfile -File D:\engramnote\scripts\backup.ps1" /sc daily /st 03:00
```

### 启用后影响

- 每天磁盘占用增加（单库约 38MB × 保留份数）
- **与现有 celery-beat 备份并存**：两者写不同目录（`_backup/scheduled/` vs `_backup/<date>-daily/`），不冲突
- 若磁盘紧张，需要同时调小保留策略

### 回滚

```powershell
schtasks /delete /tn "EngramNote-Backup" /f
```
